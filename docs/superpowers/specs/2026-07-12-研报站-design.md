# 研报站(ai-research-hub)设计文档

> 日期:2026-07-12
> 状态:设计已确认,待写实现计划
> 脚手架来源:`~/myCode/docmind`(用户自有的 RAG 问答系统)

## 1. 定位

一个**本地运行的精致研报阅读站 + 单篇 AI 问答**。用户手动上传精选的 markdown 研报(如茅台、碳酸锂投资研究报告),站点将其排版成好读的文章;每篇报告旁挂一个**针对当前这篇**的 AI 问答,答案带**溯源回链**——点击引用可跳回原文对应章节并高亮。

以 docmind 为脚手架整包复制改造。provider 全部使用智谱(GLM 生成 + embedding-3 向量),单一 API key。首版仅本地运行(`npm run dev`),无登录。

### 非目标(首版明确不做,YAGNI)

- 全库/跨报告问答(后续再做,首版仅单篇)
- docmind 的记忆系统(SQLite memory notes + 语义记忆)
- docmind 的 RAG 自动评估系统(eval 出题 + LLM-as-Judge)
- 精排 rerank
- 登录 / 访问控制
- 元数据自动抽取(公司/类型/评级)
- 按公司聚合的浏览视图
- Docker 上线部署(配置留着,首版不碰)

## 2. 关键决策记录

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 项目落地 | 全新独立仓库(`~/myCode/` 下,与 docmind 平级) | 阅读站前台与 docmind"上传即问"形态差异大,独立最干净;docmind 保持不动 |
| 语料来源 | 精选上传(像 docmind),**不**全量导入 2114 篇 | 用户只上传手挑的一部分报告 |
| 产品形态 | 阅读站为主 + AI 问答辅助 | 好看好读的研报站 + 问答加持 |
| 首页组织 | 报告卡片流,最新在前 | 类研报门户;不做公司聚合 |
| 元数据 | 不解析,文件名(或首个 `#` 标题)即展示名 + 上传日期 | 用户明确"叫什么就展示什么名字",省心 |
| 问答范围 | 单篇问答(限当前报告) | 简单、精准、天然好溯源;全库后续再说 |
| 溯源回链 | 首版就做 | 按标题分块的"免费副产品",投研站最出彩的信任点 |
| LLM / embedding | 全智谱:GLM 生成 + embedding-3 向量 | 单 key、最省钱;直接复用 docmind 智谱链路 |
| 部署 | 首版纯本地个人用,无登录 | 先把功能做扎实 |

## 3. 架构

沿用 docmind 的 pnpm monorepo:

```
ai-research-hub/
├── packages/
│   ├── server/   Fastify + TypeScript(tsx runtime)—— 复用 docmind 后端,改造 3 处
│   └── client/   React 19 + Vite —— 大改前端(阅读站是新的)
├── data/         SQLite(报告元信息 + 分块)+ 上传的 markdown 原文
├── docker-compose.*.yml   保留但首版不使用
└── pnpm-workspace.yaml
```

- **关系型存储**:SQLite(better-sqlite3),存报告元信息与分块(含章节路径)。
- **向量存储**:ChromaDB + 智谱 embedding-3(复用 docmind)。
- **流式**:SSE(复用 docmind)。

## 4. 后端改造(相对 docmind)

### 4.1 改动点

1. **`pdfParser.ts` → `markdownParser.ts`(核心改动)**
   - 按 markdown 标题(`#`/`##`/`###`)分块,取代 docmind 的定长 500 字递归分块。
   - 每块记录:章节路径(如 `§1.3 大事件的规律与启示`)、标题层级、在原文中的字符起止位置(anchor,供前端滚动定位)。
   - 过长的章节(超过阈值,如 1500 字)在段落边界二次切分,但保留同一 §章节路径。
   - 这是溯源回链正确性的根基。

2. **`routes/documents.ts`**
   - 接收 `.md` 上传;存原文入库;用文件名(去扩展名)或正文首个 `#` H1 作为展示名。
   - 不解析元数据(公司/类型/评级)。
   - 列表 / 删除逻辑照旧。

3. **`routes/chat.ts`**
   - 检索限定 `doc_id = 当前报告`(ChromaDB 已支持按 doc 过滤)。
   - 生成时把命中块的**章节标注**注入 prompt,指示 GLM 在答案中输出 `【来源 §x.x 章节名】` 形式的引用标记。
   - 返回结构里附带命中块的 anchor 信息,供前端回链定位。

### 4.2 复用不动

- `llm.ts`(智谱链路 `streamZhipu`)、`embeddings.ts`(智谱 embedding-3)、`documentVector.ts`(ChromaDB `docmind_docs` collection,改集合名)、SQLite 连接与 `documentStore.ts`、`chatGeneration.ts`(断线续跑持久化)、SSE 流式。

### 4.3 移除

- `services/memoryStore.ts` / `memoryVector.ts`、`routes/memory.ts`、`routes/eval.ts` 及 `eval*.ts`、`tools/weather.ts`、`llmThrottle.ts`(eval 专用)。

## 5. 前端(基本全新)

- **首页**:报告卡片流(最新在前),卡片显示报告名 + 上传日期 + "读/问"入口;顶部上传按钮。
- **阅读页**:
  - 左:自动生成的章节目录(TOC),来自 markdown 标题。
  - 中:markdown 精致渲染——表格、★评分、大师语录块(`>` 引用)、ASCII 走势图(等宽 `pre` 块保留)、来源链接。用 `react-markdown` + `remark-gfm`。
  - 右/底抽屉:单篇问答面板(复用 docmind SSE 流式渲染)。
- **问答 + 溯源回链**:答案中的 `【来源 §1.3】` 渲染为可点 chip → 中间正文滚动到该节标题 + 高亮数秒。
- **状态钩子**:`useChat` 改造为按 `docId` 建会话(去掉 docmind 的多会话 sidebar、记忆面板)。

## 6. 数据流

```
上传 碳酸锂.md
  → 存原文 + 文件名入 SQLite
  → markdownParser 按标题分块(每块带 §章节路径 + anchor)
  → 智谱 embedding-3 向量化 → 存 ChromaDB(带 doc_id + 章节元数据)

读:  首页卡片 → 阅读页渲染原文 + 左侧 TOC

问:  "三条铁律?" → 检索该 doc 的块(ChromaDB filter doc_id)
     → GLM 生成带【来源 §x.x】的答案(SSE 流式)
     → 前端把【来源】渲染成 chip → 点击滚动到该节并高亮
```

## 7. 测试策略

- **分块器单测(重点)**:给定 markdown 输入 → 断言正确的章节切分、§路径、anchor 位置。溯源正确性依赖于此。用碳酸锂 / 茅台报告作为 fixture。
- **端到端手测脚本**:上传碳酸锂报告 → 提问 → 验证答案含正确 §引用 → 验证 chip 能滚动定位。
- **类型检查**:沿用 docmind 现状(无 lint / test runner 配置,`tsc --noEmit` 做类型检查)。首版为分块器引入最小单测(如 vitest / node:test)。

## 8. 里程碑拆分(供实现计划参考)

1. **脚手架**:复制 docmind → 新仓库,移除记忆/eval/weather,改集合名,跑通空壳(能启动、能上传 txt)。
2. **分块器**:`markdownParser.ts` + 单测,替换 PDF 解析。
3. **上传与索引**:markdown 上传 → 分块 → embedding → ChromaDB(带章节元数据)。
4. **阅读站前端**:首页卡片流 + 阅读页(TOC + markdown 渲染)。
5. **单篇问答**:按 docId 会话 + SSE 流式,检索限定当前 doc。
6. **溯源回链**:prompt 注入章节标注 → 答案 chip → 滚动高亮。
7. **打磨**:排版细节(表格/★/语录/ASCII 图)、端到端手测。
