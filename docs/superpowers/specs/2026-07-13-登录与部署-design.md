# 研报站 登录 + 角色 + 限次 + 对话保存 + 部署 设计文档

> 日期:2026-07-13
> 状态:设计已确认,待写实现计划
> 来源:移植/适配 `~/myCode/docmind` 的 auth 与部署实现

## 0. 概述与分解

把研报站从"本地个人、无登录"升级为"**真·多人在线**"的公开研报站:GitHub 登录、三类身份、问答限次、按人保存对话,并打包可一键部署。

**分解为两个子系统,各出一份实现计划、依次实现:**
- **子系统 A — 登录/角色/限次/对话**:功能本身,可用 `AUTH_DISABLED=true` 或 localhost OAuth 在本地跑通。
- **子系统 B — 部署**:把 A 打包成"一条命令部署到远程服务器"。依赖 A 完成。

# 子系统 A:登录 + 角色 + 限次 + 对话保存

## A1. 访问模型(三类身份)

| 身份 | 读报告 | 问答 | 传/删研报 | 看 trace | 次数上限 |
|---|---|---|---|---|---|
| 匿名(未登录) | ✅ | ❌(引导登录) | ❌ | ❌ | — |
| 登录普通用户 | ✅ | ✅ | ❌ | ❌ | 每人 10 次 |
| 管理员 | ✅ | ✅ | ✅ | ✅ | 无限 |

- 另有**全局总上限**:全站累计成功问答达到 `GLOBAL_LIMIT` 后,普通用户被拒;管理员豁免。
- **管理员认定**:手动改 DB(照搬 docmind)——`UPDATE users SET is_admin=1 WHERE username='<GitHub 用户名>'`,`unlimited` 同理手动置 1。无写 API。

## A2. 后端 auth(移植 docmind)

- **`services/userStore.ts`**(移植,改 DB import 为 `./db.js`):`users` 表(id/github_id/username/avatar_url/message_count/unlimited/is_admin/created_at)、`upsertGithubUser`、`getUserById`、`incrementMessageCount`、`canSend`、`remaining`、`initUserTables`、`MESSAGE_LIMIT`(默认 10)。
- **`routes/auth.ts`**(移植):GitHub OAuth——`GET /api/auth/github`(跳转授权)、`GET /api/auth/github/callback`、`GET /api/auth/me`、`POST /api/auth/logout`;导出 `currentUser`/`requireUser`/`requireAdmin`。`AUTH_DISABLED=true` 时返回合成管理员(本地开发免 OAuth)。
- **`index.ts`**:注册 `@fastify/cookie`(签名 cookie,`COOKIE_SECRET`)、`initUserTables(db)`、`authRoutes`。
- env:`GITHUB_CLIENT_ID`、`GITHUB_CLIENT_SECRET`、`APP_URL`、`COOKIE_SECRET`、`AUTH_DISABLED`、`MESSAGE_LIMIT`、`GLOBAL_LIMIT`。

## A3. 限次

- **每人 10 次**:复用 docmind `message_count` + `canSend()`(`MESSAGE_LIMIT` 可配)。
- **全局上限(新增)**:新增单行计数存储 `usage`(`total_count`),`GLOBAL_LIMIT` 默认(如 1000,可配)。
  - 新文件 `services/usageStore.ts`:`initUsageTable(db)`、`getGlobalCount(): number`、`incrementGlobalCount(): void`、`globalRemaining(): number`。
  - `/chat/stream` 生成**前**:普通用户若 `!canSend(user)` 或 `getGlobalCount() >= GLOBAL_LIMIT` → 403 带剩余信息;管理员两者皆豁免。成功一次后 `incrementMessageCount(user.id)` + `incrementGlobalCount()`。

## A4. 门禁改造(现有路由加守卫)

- `POST /api/documents`、`DELETE /api/documents/:id` → `requireAdmin`。
- `GET /api/documents`、`GET /api/documents/:id` → 公开(匿名可读,不变)。
- `GET /api/traces`、`/traces/stats`、`/traces/:id` → `requireAdmin`(当前无守卫)。
- `POST /api/chat/stream` → `requireUser` + A3 限次;`GET /api/chat/messages` → `requireUser`。

## A5. 对话保存(每人每篇一条线程,精简自研)

不照搬 docmind 重型多会话(标题/多线程/压缩/generating)。按 `(user_id, doc_id)` 存一条问答历史:

- **`services/chatStore.ts`**(自研,精简):
  - 表 `chat_messages(id, user_id, doc_id, role, content, sources_json, seq, created_at)`,索引 `(user_id, doc_id, seq)`。
  - `initChatTable(db)`、`appendMessage(userId, docId, {role, content, sources?}): void`、`getMessages(userId, docId): ChatMessageRow[]`(按 seq 升序)。
- **`routes/chat.ts`**:`/chat/stream` 在生成时落库(user 消息 + assistant 消息含 sources_json);新增 `GET /api/chat/messages?docId=` → `{ messages }`(仅当前用户)。
- 匿名用户不落库、不加载(无 user 身份)。

## A6. 前端

- **`hooks/useAuth.ts`**(移植/精简):`GET /api/auth/me` 取当前用户(`{username, avatarUrl, isAdmin, remaining, ...}`);`login()` = `window.location.href = '/api/auth/github'`;`logout()` = `POST /api/auth/logout` 后刷新。
- **登录态 UI**:
  - 首页 header 右侧:未登录显示"用 GitHub 登录";已登录显示头像 + 用户名 + 剩余次数 + 登出。
  - **按角色隐藏**:非管理员不渲染"上传/删除"按钮与 "🔍 trace" 入口(后端守卫兜底)。
- **阅读页问答区**:未登录时用 `LoginGate`(移植/精简)提示"登录后提问",输入框禁用;已登录正常。进报告时 `GET /api/chat/messages?docId=` 恢复该用户历史;每轮问答后本地已有,刷新后由接口恢复。
- **剩余次数**:普通用户问答区显示"剩余 N 次";用尽或全局用尽时禁用输入并提示。

## A7. 测试(子系统 A)

- `usageStore` 单测(全局计数增/查/剩余)。
- `chatStore` 单测(append/get 往返、按 user+doc 隔离、seq 递增)。
- 手测(`AUTH_DISABLED=true`):匿名可读不可问 → 登录后可问 → 传删/trace 仅管理员可见 → 提问 10 次后普通用户被拒 → 全局上限触发 → 对话刷新后恢复。

# 子系统 B:部署

## B1. 目标

把 A 打包成"本地一条命令 `./deploy.sh` 部署到远程服务器",架构照搬 docmind:Cloudflare → host nginx(443)→ client 容器(nginx,仅回环 8080)→ server 容器(3001)→ chroma 容器(8000)。

## B2. 移植/适配的文件

- **`packages/server/Dockerfile`**(移植):node:20-alpine + `apk add python3 make g++`(better-sqlite3 原生编译;alpine g++ 支持 c++20,可源码构建,不受本机旧 clang 限制)+ `tsx src/index.ts`。
- **`packages/client/Dockerfile`** + **`packages/client/nginx.conf`**(移植):多阶段构建 → nginx 提供 SPA,`/api` 反代 server。
- **`docker-compose.prod.yml`**(移植适配):chroma + server(`env_file: .env.prod`,`CHROMA_URL=http://chroma:8000`,`RAG_MAX_K=10`)+ client(绑 `127.0.0.1:8080`);持久卷 chroma_data / server_data。集合名 `research_docs`。
- **`deploy.sh`** + **`scripts/setup-remote.sh`**(移植):SSH docker context 远程构建部署;`.env.prod` 只读自本地、不入服务器磁盘/镜像/git。
- **`packages/server/.env.prod.example`**(新增模板):`ZHIPU_API_KEY`、`GITHUB_CLIENT_ID/SECRET`、`APP_URL=https://<域名>`、`COOKIE_SECRET`、`GLOBAL_LIMIT`、`MESSAGE_LIMIT`。`.env.prod` 加入 `.gitignore`。
- **`docs/DEPLOY.md`**(移植适配):架构图 + 一次性准备(注册 GitHub OAuth app、填 `.env.prod`、`setup-remote.sh`)+ 部署(`deploy.sh`)+ host nginx/Cloudflare 说明 + "密钥怎么到服务器"。

## B3. 边界(能做 vs 你来做)

| 我做 | 用户做(DEPLOY.md 给精确步骤) |
|---|---|
| 移植适配全部部署件 | 提供服务器(VPS + SSH key auth)、域名、Cloudflare |
| 本地 `docker compose -f docker-compose.prod.yml build` 通过 + 本地起栈冒烟(`AUTH_DISABLED=true`,验证三容器能跑、能读能问) | 在 GitHub 注册 OAuth app 拿 `CLIENT_ID/SECRET`(账号动作,不可代做) |
| 写全 `.env.prod.example` 占位 | 填 `.env.prod` 真实密钥、跑 `setup-remote.sh`/`deploy.sh` 上线 |
| DEPLOY.md 全流程文档 | 首次登录后手动 `UPDATE users SET is_admin=1` 把自己设为管理员 |

**明确:不替用户把站点推上公网**(无其服务器/域名;注册 OAuth app 是其账号动作)。交付"备齐+本地验证"的部署件。

## B4. 测试(子系统 B)

- `docker compose -f docker-compose.prod.yml build` 三镜像构建成功。
- 本地起栈(临时 `AUTH_DISABLED=true` + 本机 `ZHIPU_API_KEY`):访问 client 容器端口 → 能看首页、能读报告、能问答、trace 可见(合成管理员)。
- 冒烟后清理本地栈。

## B5. 里程碑

**Plan 1(子系统 A)**:userStore/auth 移植 → cookie/装配 → usageStore 全局限次 → 门禁守卫 → chatStore 对话保存 → 前端 useAuth/LoginGate/角色隐藏/历史恢复 → 手测。
**Plan 2(子系统 B)**:Dockerfile×2 + nginx.conf → compose.prod → deploy/setup 脚本 + .env.prod.example → DEPLOY.md → 本地 build + 冒烟。

## 非目标

- 不做邮箱/密码登录、不做第三方 IdP(仅 GitHub OAuth)。
- 不做管理员后台 UI(改权限、调 GLOBAL_LIMIT 走 DB/env)。
- 不替用户注册 OAuth app、不替用户上线到公网。
- 不做全库问答、告警、自动扩缩容。
