# 公司研报与行业研报的组织

## 背景

站点至今只有一种研报:`industry-research` 产出的产业链报告(《碳酸锂产业链投资研究报告》
《腾讯生态产业链……》),首页是按更新时间排的平铺列表。`documents` 表没有任何"这是哪一类"的字段。

现在有了只针对**单家公司**的研报(`investment-research` 产出,如《中国海洋石油(0883.HK / 600938.SH)
投资研究报告》《SK 海力士(KRX: 000660 / NASDAQ: SKHY)投资研究报告》)。两类的差别:

| | 行业研报 | 公司研报 |
|---|---|---|
| 主角 | 一条产业链,公司是其中的 5.x 小节 | 一家公司 |
| 标题 | `XX产业链投资研究报告` | `XX(代码)投资研究报告` |
| 更新 | 随行业事件 | 随财报 / 价格,按日期出新版 |

## 决策

**加一个二值字段 `kind`(`industry` / `company`),不建行业分类树,不建公司实体。**

- 库里的研报才十来篇,公司类只有个位数,撑不起标签体系或聚合页。
- 站点上"行业"从来不是数据,只是内容。按标题关键词猜行业标签的做法
  (`client/src/lib/reportTags.ts`)因为"猜错只会安静地标错"已经下线,新字段不能重蹈。
- 公司聚合页(同一家公司的公司研报 + 提到它的行业研报 + 信号)是对的方向,但留到公司类
  攒够以后。届时用标题里的代码做键,`kind` 不会白做。

## 行为

### 类型从哪来

- **上传时由管理员在弹窗里显式选**(行业研报 / 公司研报)。选择器预填一个建议值,**人必须看到并能改**。
- 建议值 `inferKind(title)`,只看 H1,规则按优先级:
  1. 含"产业链" → `industry`
  2. 含股票代码(`600519.SH` / `09696.HK` / `0700 HK` / `NYSE: ALB` / `KRX: 000660` / `NVDA.O`) → `company`
  3. 含"行业" → `industry`
  4. 都不是 → 无建议,弹窗默认 `industry`
- **顺序是产业链 → 代码 → 行业**:产业链报告标题里也可能带代码,所以"产业链"先判;但"行业"不可靠,
  公司研报常写「白酒行业龙头」,所以它让给代码。
- **刻意不认括号里的裸字母**(`苹果（AAPL）`):和 `（HBM）` `（CNOOC）` 这类缩写长得一样,认了会把主题报告
  预填成公司研报。认不出就是无建议,管理员自己选。已知局限:指数代码(`中证500（000905）`)会被判成公司,
  只是预填,管理员能看到并改。
- 直接调接口不带 `kind` 时服务端自己用 `inferKind`,拿不准按 `industry`。
- 上传新版本不改 `kind`,继承原文档。
- 管理员可事后改类型(`PATCH /api/documents/:id`),预填错了不必删掉重传 —— 删除会连版本和问答记录一起丢。

### 存量

列默认 `industry`。**不能一刀切**:库里已经有《贵州茅台(600519.SH)投资研究报告》这样的公司报告。
一次性迁移(`runOnce`)对存量标题跑 `inferKind`,推出 `company` 的改过去,其余保持 `industry`。
《投研方法论》《港股互联网:估值重估》这类非产业链主题文章落在 `industry`,即"非公司研报"。

### 首页

- 栏目头下方出现分段筛选 **全部 / 行业 / 公司**,带计数,状态放在 URL(`/?kind=company`),
  刷新、分享、浏览器后退都对。
- **库里还没有公司研报时不显示筛选**(别给用户一个永远为空的选项)。
- "全部"视图里公司研报的标题后挂一个"公司"小标;筛选到公司视图时不挂(冗余)。
- 公司研报的标题本身就带代码,所以**不另存、不另显 ticker**。

### 查重

上传前查重里,类型**只用来压掉"标题 / 主题撞词"的误报,不用来排除正文本身**:`findSimilarReports`
在上传和候选两边的 `kind` 都已知且不同时,候选只有**正文重合过线**(`CONTENT_MIN`)才保留。否则 CNOOC 公司研报会和库里的《中国海洋石油(CNOOC)产业链投资研究报告》
撞上 —— 共享"中国海洋石油"这个高区分度的词,标题分过线,弹窗会建议"作为它的新版本",而这是两篇不同的报告。

这个"正文过线则保留"是必须的:库里每一行都有确定的 `kind`,上传方的类型却可能被推断错
(标题写「白酒行业龙头」的茅台公司研报),如果跨类就整篇排除,正文一模一样的旧版本会被漏掉,
静默建出重复的一篇。不同研报之间正文重合最高约 3%,同公司的公司研报与产业链报告也不到 6%,
所以过线就是同一篇。跨类保留下来的候选,弹窗里会注明"库里是公司研报",方便判断。

上传方的 `kind` 优先取管理员在弹窗里选的,其次取 `inferKind` 的建议;**都没有就不分类过滤**
(宁可多提示,不可漏掉真正的旧版本)。管理员改了类型选择,弹窗用新类型重新查一次。

## 不做

- 行业标签 / 板块浏览 / 行业层级。
- 公司实体与聚合页、阅读页的"同公司其他研报"。
- 信号看板改动。公司研报的 H1 带代码,现有标题抽取已经能把港/美股代码收进自选股;
  A 股(`600938.SH`)与韩股(`KRX`)按既有规则丢弃,`NASDAQ: SKHY` 是 2026-07 才上市的 ADR,
  日线不足 120 根只会显示"数据不足"。这是既有行为,不在本次范围。
- 评测集(`evalset/`)与问答:都按单篇文档工作,与类型无关。

## 数据模型

```sql
ALTER TABLE documents ADD COLUMN kind TEXT NOT NULL DEFAULT 'industry'
  CHECK (kind IN ('industry', 'company'));
```

启动时发现缺列才执行(`PRAGMA table_info`),与既有"建表即升级"的做法一致。
