# 手动添加自选股(管理员)

## 背景

自选股列表目前**完全由研报标题驱动** —— 上传研报时用正则从标题抽代码,抽不到就没有。
这是「股票信号追踪」立项时定的取舍(见 `2026-08-21-股票信号追踪-design.md` 的「非目标」):
只看标题、宁缺毋滥,不让假代码污染看板。

上线后这个取舍的代价显形了。以《商业航天产业链投资研究报告》为例,它的标题写法是:

```
### 4.1 SpaceX（SPCX）★★★☆☆
### 4.2 Rocket Lab（RKLB）★★★★☆
### 4.3 Karman Holdings（KRMN）★★★★☆
### 4.4 AST SpaceMobile（ASTS）★★☆☆☆
### 4.5 Iridium（IRDM）★★★☆☆
```

**裸代码,没有 `NASDAQ:` 前缀** —— 而抽取器刻意拒绝裸字母,因为同一篇里还有
`### 3.5 ETF`、`### AI 研究偏见自查` 这类章节标签,接受裸字母就会把 `ETF` / `AI`
当成股票代码。于是这篇研报抽出 0 只,尽管里面有 5 只真实上市的票。

实测过放宽规则的效果:「只接受括号内裸大写代码」这条规则在全部 7 篇研报上得到
6 真 2 假,而 Yahoo 的 404 兜底只挡掉其中一个 —— `HBM`(存储技术缩写)在 Yahoo 上
是加拿大铜矿 Hudbay Minerals,会带着一只完全无关的矿业股进存储芯片研报的自选股。
**代码合法、Yahoo 也认、但公司不对**,这类错误 404 兜底抓不住。

所以不放宽正则,改为给管理员一个手动入口。

## 目标

管理员在 `/signals` 上手动添加标的,添加前先探测并确认公司身份;误加的可以删除,
删掉的不会被下一次「重新抽取」带回来。

## 非目标

- **不放宽抽取正则。** 「只从标题抽、只接受带交易所前缀或 `.HK` 后缀的代码」这条不变
- **不做批量导入。** 一次加一个
- **不做编辑。** 加错了删掉重加
- **不做分组 / 标签 / 排序。** 看板顺序仍由后端按最近翻转倒序给出

## 方案选择

**采用:添加前探测并让管理员确认公司身份;删除用软删除墓碑。**

### 为什么探测后还要人工确认

仓库已有先例:站点默认模型在保存前会用站长 key 对新模型名实际调一次
(`2026-08-16-站点默认模型切换-design.md`),理由是「模型名填错会让全站提问失败,
而管理员要到下一次有人提问时才发现」。

这里的风险同构但更隐蔽:`HBM` 那类错误**探测会成功**,拿回来的是一家真实公司,
只是不是你想要的那家。所以光探测不够,必须把公司全名和交易所摆到管理员面前让他确认。

已否决:
- **直接入库,下次扫描再说** —— 代码拼错会被标 `invalid`,但公司弄错那类永远不会被发现,
  它扫得好好的
- **探测但不确认** —— 挡得住 404,挡不住 `HBM`

### 为什么软删除而不是硬删除

删掉的标的不能被下一次「重新抽取」带回来。软删除的墓碑行天然做到这点 ——
`addWatchlistEntry` 已经是 `INSERT ... ON CONFLICT(symbol) DO NOTHING`,墓碑行占着主键,
那条 INSERT 直接冲突、什么都不做。**不需要黑名单表,也不需要改抽取逻辑。**

已否决:**硬删除 + 黑名单表** —— 多一张表、多一层状态,而且「想重新启用」时又得有地方
把它从黑名单里拿出来。

### 为什么复用 `enabled` 列而不新增 `deleted`

`enabled = 0` 即「已删除」。省掉一次线上迁移,而且生产库 13 行全是 `enabled = 1`,
没有正在被禁用的行需要区分。代价是列名与语义不完全贴合 —— 用建表注释与函数命名
(`softDeleteWatchlistEntry` 而非 `setWatchlistEnabled`)补上,列名不动。

**「禁用」这个功能同时被移除。** 此前表格上那个启用开关不再存在,操作栏只有删除。

## 数据层

**表结构不变。** `watchlist.enabled` 的语义从「启用/禁用」改为「未删除 / 已删除」,
在建表语句处加注释说明。

`packages/server/src/services/watchlistStore.ts` 的改动:

| 函数 | 变化 |
|---|---|
| `listScannable()` | 不变(`enabled = 1 AND status != 'invalid'` 语义恰好仍然正确) |
| `listWatchlist()` | 加 `WHERE enabled = 1` —— 墓碑不应出现在界面上 |
| `setWatchlistEnabled(symbol, enabled)` | **改名** `softDeleteWatchlistEntry(symbol)`,只做 `enabled = 0` |
| `addWatchlistEntry(...)` | **不变**。墓碑行使 `ON CONFLICT DO NOTHING` 天然阻止抽取复活已删除的标的 |
| `reviveWatchlistEntry(symbol)` | **新增**。把 `enabled` 置回 1 并清空 `status` / `last_error`,供手动添加已删除的代码时复活 |

**删除时连同该标的的日志一起清除** —— `replaceStates(symbol, tf, [])` 与
`replaceEvents(symbol, tf, [])` 对两个周期各调一次(这两个函数传空数组即等于清空,
已有测试覆盖)。理由:一只票约 1200 行 `daily_states`,删了还留着是再也不会更新、
也没人看的死数据。代价是删错后重新添加要等一次扫描 —— 手动点「立即扫描」几秒即可。

## 标的探测

新增 `packages/server/src/services/signals/probeSymbol.ts`:

```ts
export interface ProbeResult {
  symbol: string        // 归一化后的 Yahoo 口径代码
  market: Market
  name: string | null
  currency: string | null
  exchange: string | null
  bars: number          // 可用的已收盘日线根数
  enough: boolean       // bars >= MIN_BARS
  alreadyListed: boolean // 已在自选股里(未删除)
  deleted: boolean       // 曾被删除,添加即复活
}
export function probeSymbol(raw: string, deps?): Promise<ProbeResult>
```

流程:`normalizeSymbol(raw)` → 不通过则抛「只支持美股与港股」;通过则
`fetchDailyQuotes(symbol)` → `YahooError.kind === 'not_found'` 抛「Yahoo 上查不到」;
成功则返回上述结构。

`enough === false` **不阻止添加**,只在界面上提示。这正是 SpaceX 的情况:
`SPCX` 于 2026-06-12 上市,当前仅 49 根日线,不足 `MIN_BARS`(120),添加后会被标
`insufficient`、暂时不出信号,约需到 2026 年 12 月才够。管理员应该能提前把它加进来占位。

## API

`packages/server/src/routes/signals.ts`:

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/signals/watchlist/probe` | **admin** | `{ code }` → `ProbeResult`;归一化失败或 404 返回 400 |
| POST | `/signals/watchlist` | **admin** | `{ symbol }` → 写库(已删除的则复活);返回 `{ ok: true }` |
| DELETE | `/signals/watchlist/:symbol` | **admin** | 软删除 + 清两个周期的日志与事件 |
| ~~PATCH~~ | ~~`/signals/watchlist/:symbol`~~ | — | **移除**(禁用功能不再存在) |

`POST /signals/watchlist` 接受的是**已归一化的 symbol**(前端从 probe 结果里拿),
不再重复归一化 —— 避免「探测的是一个代码、存进去的是另一个」。
若该 symbol 不存在于表中则插入(`source_doc` / `source_text` 为 `null`,表示手动添加);
若存在且 `enabled = 0` 则复活;若存在且 `enabled = 1` 则返回 409「已在自选股中」。

## 前端

- `packages/client/src/components/AddSymbolModal.tsx`(新增)—— 探测 + 确认两步的弹窗
- `packages/client/src/pages/SignalsPage.tsx` —— 管理员按钮区加「添加标的」;
  表格末尾的「启用」开关列换成「操作」列,只有一个带 `Popconfirm` 的「删除」
- `packages/client/src/api.ts` —— 新增 `probeSymbol` / `addSymbol` / `deleteSymbol`;
  **移除** `setWatchlistEnabled`
- `packages/client/src/hooks/useSignals.ts` —— `setEnabled` **改名** `remove(symbol)`,
  新增 `add(symbol)`。两者与既有的 `scan` / `extract` 一样,成功后 `refresh()` 并
  `setVersion(v => v + 1)` —— 那个 `version` 是横幅与展开行日志重新拉取的信号,
  增删标的必须触发它,否则横幅上会留着已删标的的事件
- `packages/client/src/types.ts` —— 新增 `ProbeResult`

弹窗交互:输入代码 → 点「查询」→ 展示公司全名 / 交易所 / 币种 / 历史根数 →
「确认添加」才落库。**查询成功前「确认添加」禁用。** 已在列表中的给出提示并禁用添加;
曾被删除的提示「将恢复该标的」。

## 测试策略

| 模块 | 测法 |
|---|---|
| `probeSymbol.ts` | 注入假 `fetchDailyQuotes`;覆盖归一化失败、404、`enough` 真假、已存在、已删除五条路径 |
| `watchlistStore.ts` | `listWatchlist` 排除墓碑;`softDeleteWatchlistEntry` 后 `listScannable` 不再返回它;`addWatchlistEntry` 不复活墓碑(**这条是「删了不会回来」的回归护栏**);`reviveWatchlistEntry` 正确复活 |
| `routes/signals.ts` | 三个新路由的鉴权(未登录 401)、参数校验(400)、409 重复添加;删除后日志与事件确实被清空 |
| 前端 | `AddSymbolModal` 的「查询成功前确认按钮禁用」「探测失败显示错误」;`SignalsPage` 的操作列仅管理员可见 |

测试不得访问真实网络 —— `probeSymbol` 的 `fetchDailyQuotes` 经参数注入。

## 已知取舍

- **一次只能加一个。** 商业航天那篇有 5 只要加,得点 5 次。批量导入留给后续
- **手动添加的标的没有「来源」。** 看板来源列显示「—」,无法追溯是为什么加的
- **删除是不可撤销的**(日志被清)。墓碑仍在,重新添加会复活,但历史要重新扫
- **抽取正则仍然拒绝裸代码。** 这个功能是绕过它的手段,不是修复它。若日后发现
  手动添加过于频繁,应重新评估「只接受括号内裸代码」那条规则(实测 6 真 2 假)
