# 股票信号追踪(SuperTrend 看板)

## 背景

站点目前只有「研报」这一个维度:`documents` 表只存 filename / size / chunk_count,
没有任何标的(ticker)概念,也没有接过任何行情数据源。

而研报本身是围绕具体公司写的。以库里现有的《碳酸锂产业链投资研究报告》为例,
第五部分的章节标题直接带着代码:

```
## 5.1 天齐锂业(002466 / 09696.HK)
## 5.4 SQM(NYSE: SQM)
## 5.5 Albemarle(NYSE: ALB)
```

读完研报形成观点之后,缺的是「这些票现在什么状态」的持续跟踪。本设计补上这一层:
把研报里提到的标的自动收进自选股,每日收盘后计算 SuperTrend,落库成可回溯的日志,
在看板上呈现。

## 目标

- 从研报**标题**中自动识别标的,收进自选股
- 每个交易日收盘后计算日线 / 周线两个周期的 SuperTrend
- **保留每天的状态日志**,可回溯任意历史交易日
- 看板一屏看到:当前趋势方向、最近一次翻转、距止损线距离、日周共振情况

## 非目标

- **不做盘中**。SuperTrend 在收盘前会随价格反复翻转(重绘),盘中值没有意义。
  全系统只处理已收盘的 bar。
- **不做 A 股**。只支持美股与港股(见「标的抽取与归一化」的市场过滤)。
- **不抽正文**。只从标题抽代码,标题里没有就不加入自选股。正文里的公司扫描表格
  (第四部分)召回率更高,但需要 LLM 抽取与人工确认,留给后续。
- **不做告警推送**。第一版只有看板,不发邮件 / 飞书 / 站内信。
- **不做 K 线图**。看板是表格,不引图表库。单股详情页留给后续。
- **不做其他指标**。只有 SuperTrend。均线 / RSI / MACD 留给后续。
- **不做手动添加自选股**。列表完全由研报标题驱动;但支持 admin 禁用误抽的行。

## 方案选择

**采用:cron 每日收盘后全量重算 + 服务启动时无条件补扫。**

已评估的另一方案:**请求时惰性回算,不要 cron**。因为 Yahoo 一次请求就返回完整
历史,「过去每天的状态」本就可以回算出来,不需要真的每天记一次。该方案不引入调度
设施,漏跑不会有洞。

选 cron 的理由是它更贴近使用直觉(盘后一次性算完,打开看板纯读库、秒开),
且代价被下面这个决定抵消了大半 —— **两条路径共用同一个全量重算函数**,
cron 与补扫不是两套实现。

### 全量重算,不做增量

cron 每天只需拉增量(`range=5d`)、从上一条日志恢复 `up/dn/trend` 状态接着算。
**明确否决**,理由:

- SuperTrend 是递归指标。增量路径一旦某天算错,会沿着递归**永久传递**,无自愈机会
- 改 ATR 参数时增量不会重算历史,库里会混着两套参数的脏数据
- 它与「启动补算」是两条不同的代码路径,等于同一个引擎要正确两次

全量重算是幂等的,跑一遍和跑一百遍结果相同。代价只是流量:
**40 只票 x 130KB ≈ 5MB/天,一天一次**,不值得为它引入状态机。

这个决定还白送了两个好处:节假日空跑无害(不需要交易日历),
改 ATR 参数后历史日志自动跟着重算。

## 数据源(已实测)

```
GET https://query1.finance.yahoo.com/v8/finance/chart/{symbol}
      ?interval=1d&range=5y&includeAdjustedClose=true
Header: User-Agent: Mozilla/5.0        # 不带 UA 会被 429
```

2026-08-21 实测结果:

| 标的 | HTTP | 日线根数 | 起始日 | JSON |
|---|---|---|---|---|
| `ALB` | 200 | 1254 | 2021-08-23 | 133 KB |
| `9696.HK` | 200 | 1010 | 2022-07-13 | 101 KB |

响应结构:`chart.result[0]` 下三部分 —— `meta`、`timestamp[]`、
`indicators.quote[0].{open,high,low,close,volume}` 与
`indicators.adjclose[0].adjclose[]`。**`timestamp` 与各价格数组平行、靠下标对齐**,
`close` 中可能出现 `null`(停牌日),解析时需一并跳过该下标。

**每只票每次只发 1 个请求。周线不单独请求,从日线聚合**(实测 1254 根日线聚合出
261 根周 K,对周线 ATR(10) 预热充足)。这样请求数减半,且「本周是否已结束」由我们
自己判定,不依赖 Yahoo 的 `interval=1wk` 语义。

### 三个必须处理的数据陷阱

**① 最后一根可能未收盘**

Yahoo 会把进行中的 bar 一并返回。实测 2026-08-21 04:05 UTC(港股午盘)拉
`9696.HK`,最后一根 `2026-08-21` 的 close 就是当时的实时价 36.74。

判定:`meta.currentTradingPeriod.regular.end` 给出当日收盘的 UTC 时间戳。
若 `now < end` 且最后一根 bar 的日期等于 `meta.regularMarketTime` 的日期,
则**丢弃该 bar**。周线同理:若最后一周的 ISO 周等于今天所在的 ISO 周,丢弃。

**② 分红不复权会造出假信号**

`indicators.quote` 里的 OHLC **只做了拆股调整,没做分红调整**。实测累计缺口:

| 标的 | `adjclose/close` 最早值 | 5 年累计分红调整 |
|---|---|---|
| `ALB` | 0.9423 | 5.8% |
| `9696.HK` | 0.8894 | **11.1%** |

`9696.HK` 的两个除息日分别造成 **-5.78%**(2023-07-05)与 **-6.24%**(2024-06-14)
的名义跳空。SuperTrend 止损线离价格通常只有 5~10%,**一个大除息日足以打穿止损线,
触发纯属虚假的翻空信号**。ALB 的季度分红只有 0.25~0.65%,无害;
风险集中在港股年度大额分红上。

处理:逐 bar 计算复权因子 `f = adjclose / close`,将 `high / low / close` 全部
乘以 `f`,用这套**全复权序列跑信号**;看板**展示价格时用原始未复权价**,
否则与券商界面对不上。两套数各司其职,`daily_states` 两个都存。

**③ 上市不足 5 年很常见**

`9696.HK` 只返回 1010 根(2022-07 上市)。代码不得假设一定拿到 ~1250 根。

## 模块划分

```
研报上传/已有报告
      │ headings[]  (markdownParser 已解析好,直接复用)
      ▼
 tickerExtractor ──► symbol ──► watchlist 表
   (纯函数/regex)   (纯函数/归一化)

 cron 每日收盘后 ─┐
                 ├─► scanner ──► yahooClient ──► supertrend ──► signalStore
 启动时补扫     ─┘   (唯一编排层)  (唯一 IO)     (纯函数引擎)   (daily_states/signal_events)
                                                                      │
                                                          /signals 看板 ◄┘
```

| 新增模块 | 职责 | 依赖 |
|---|---|---|
| `services/market/symbol.ts` | 代码归一化与市场判定。**纯函数** | 无 |
| `services/market/yahooClient.ts` | 拉 K 线。**唯一碰网络的地方** | fetch |
| `services/signals/supertrend.ts` | Pine 逻辑翻译成 TS。**零 IO、零依赖** | 无 |
| `services/signals/weekly.ts` | 日线聚合为周线,丢弃未完成周。**纯函数** | 无 |
| `services/signals/tickerExtractor.ts` | 从标题串抽代码候选。**纯函数** | 无 |
| `services/watchlistStore.ts` | 自选股表 CRUD | db |
| `services/signalStore.ts` | `daily_states` / `signal_events` 读写 | db |
| `services/signals/scanner.ts` | 编排:取自选股 → 拉数据 → 算 → 落库 | 上述全部 |
| `jobs/dailyScan.ts` | node-cron 注册 + 启动补扫 | scanner |
| `routes/signals.ts` | HTTP 层 | store / scanner |

切分依据:`supertrend` / `symbol` / `weekly` / `tickerExtractor` 四个都是**纯函数,
可直接喂固定数组单测**,不需要网络或数据库。SuperTrend 的递归棘轮逻辑最容易写错
(`up[1]` 的初始化、trend 的粘性),而一旦错了整个看板的数字全错却看不出来 ——
所以它必须是能对着真实历史数据逐根校验的纯函数。IO 全部收口在 `yahooClient`,
`scanner` 是唯一把两者粘起来的地方。

## 数据层

三张新表,建表函数各自导出 `initXxxTable(db)`,在 `index.ts` 里与现有表一同初始化。

```sql
CREATE TABLE IF NOT EXISTS watchlist (
  symbol      TEXT PRIMARY KEY,      -- Yahoo 口径,如 ALB / 9696.HK
  market      TEXT NOT NULL,         -- 'US' | 'HK'
  name        TEXT,                  -- 来自 meta.longName,首次扫描时回填
  currency    TEXT,                  -- 来自 meta.currency(USD/HKD),首次扫描时回填
  source_doc  TEXT,                  -- 抽取来源的 document id
  source_text TEXT,                  -- 抽中的原始标题串,便于排错
  enabled     INTEGER NOT NULL DEFAULT 1,
  status      TEXT NOT NULL DEFAULT 'ok',   -- 'ok' | 'invalid' | 'insufficient'
  last_error  TEXT,
  last_scan_at TEXT,
  created_at  TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS daily_states (
  symbol      TEXT NOT NULL,
  timeframe   TEXT NOT NULL,         -- '1d' | '1wk'
  bar_date    TEXT NOT NULL,         -- 该市场的交易日 YYYY-MM-DD
  trend       INTEGER NOT NULL,      -- 1 | -1
  stop_line   REAL NOT NULL,         -- 多头取 up,空头取 dn
  close_adj   REAL NOT NULL,         -- 复权价,信号就是用它算的
  close_raw   REAL NOT NULL,         -- 原始价,给展示用
  atr         REAL NOT NULL,
  PRIMARY KEY (symbol, timeframe, bar_date)
);

CREATE TABLE IF NOT EXISTS signal_events (
  symbol      TEXT NOT NULL,
  timeframe   TEXT NOT NULL,
  bar_date    TEXT NOT NULL,
  direction   INTEGER NOT NULL,      -- 1 = 翻多,-1 = 翻空
  price       REAL NOT NULL,         -- 复权收盘价
  PRIMARY KEY (symbol, timeframe, bar_date)
);
```

写入一律用 `INSERT ... ON CONFLICT DO UPDATE`(upsert),使全量重算幂等。

**`bar_date` 必须取 Yahoo 返回的交易日,不能用服务器当天日期。** cron 在北京时间
凌晨 05:30 跑批时,美股交易日是「昨天」、港股交易日是「昨天」、服务器日期是「今天」,
三者不一致,用跑批日期一定错位。

看板上的派生指标 —— 「已持续 N 天」「期间涨跌幅」「近 90 天翻转次数」——
**全部从这两张表实时算出,不单独落列**,避免出现存了却没更新的陈旧字段。

## 标的抽取与归一化

### tickerExtractor(纯函数)

输入:文档标题 + 所有章节标题(复用 `markdownParser` 已解析的 headings)。
输出:`{ raw: string, docId: string, headingText: string }[]`。

用正则从标题串里捞候选,覆盖库中实际出现的三种写法:

| 标题实例 | 捞出 |
|---|---|
| `5.1 天齐锂业(002466 / 09696.HK)` | `002466`, `09696.HK` |
| `5.4 SQM(NYSE: SQM)` | `SQM` |
| `5.5 Albemarle(NYSE: ALB)` | `ALB` |
| `第四部分:全球上市公司扫描` | (无) |

**正文一概不看。标题里捞不到就不加入自选股。**

### symbol(纯函数)

输入原始串,输出 `{ symbol, market } | null`:

| 输入 | 输出 | 说明 |
|---|---|---|
| `09696.HK` / `01772` | `{ '9696.HK', 'HK' }` | 港股去掉前导 0,补 `.HK` |
| `NYSE: SQM` / `SQM` | `{ 'SQM', 'US' }` | 剥掉交易所前缀 |
| `ALB` / `LIT` | `{ 'ALB', 'US' }` | |
| `002466` / `000792` | `null` | A 股,**丢弃** |
| `PLS`(ASX) | `null` | 非美非港,**丢弃** |

对现有那篇报告,五个章节标题抽出 5 个标的,过滤后落库 4 只:
`9696.HK`、`1772.HK`、`SQM`、`ALB`(盐湖股份 `000792` 仅 A 股上市,丢弃)。

**歧义风险**:纯字母代码可能撞上普通英文词(如标题里的 `ETF`、`DLE`)。缓解:
只接受 1~5 位全大写字母,且**首次扫描时若 Yahoo 返回 404 即把该行标记 `invalid`
并不再扫描**,由数据源本身充当校验。

### 一只票被多篇研报提及

**同一标的被多篇研报提及时**,`watchlist.symbol` 是主键,只能记一个来源。
取**最早一次**(upsert 时不覆盖已有的 `source_doc` / `source_text`)。
看板「来源」列因此只显示一篇。做成多对多需要一张关联表,第一版不做 ——
当前库里只有一篇研报,收益为零。

### 触发时机

- 上传报告时自动抽(在 `routes/documents.ts` 的上传处理里 hook)
- `/admin` 提供「对全部已有报告重新抽取」按钮,遍历全部 documents 重跑抽取(幂等)

## SuperTrend 引擎

`services/signals/supertrend.ts`,签名:

```ts
type Bar   = { date: string; high: number; low: number; close: number }
type Point = { date: string; trend: 1 | -1; up: number; dn: number; atr: number }
function supertrend(bars: Bar[], opts: { period: number; mult: number }): Point[]
```

严格对齐 Pine v6 的语义:

- `TR = max(h-l, |h-c_prev|, |l-c_prev|)`,首根取 `h-l`
- `ATR = ta.rma(TR, period)` —— Wilder 平滑,**用前 `period` 根的 SMA 播种**,
  此后 `rma[i] = (rma[i-1]*(period-1) + tr[i]) / period`
- `src = hl2 = (h+l)/2`
- 棘轮:`up = close[i-1] > up_prev ? max(rawUp, up_prev) : rawUp`(`dn` 对称取 min)
- 趋势粘性:`trend = close > dn_prev ? 1 : close < up_prev ? -1 : trend_prev`,初值 1

从下标 `period-1` 开始输出(此前 ATR 未定义)。`open` 与 `volume` 全程不使用,
解析时即可丢弃。

**输入 bars 少于 120 根时直接返回空数组**(判断的是入参长度,不是输出长度),
由调用方标记为「数据不足」。预热不足的 SuperTrend 是错的,宁可不给信号。

## 扫描器

`scanner.scanAll()` —— cron 与启动补扫**共用的唯一入口**:

```
取 watchlist 中 enabled=1 且 status != 'invalid' 的行
  并发 5 (简单 promise pool):
    yahooClient 拉 5y 日线
    丢弃未收盘 bar → 计算复权序列 → supertrend(日线)
                                  → weekly 聚合 → supertrend(周线)
    upsert daily_states(两个周期的全部 bar)
    diff 出 trend 变化点 → upsert signal_events
    回填 watchlist.name / last_scan_at,清空 last_error
写入 site_settings['signals.last_scan_at']
```

单只票失败不影响其他票:

| 情况 | 处理 |
|---|---|
| HTTP 429 | 指数退避重试 2 次;仍失败则写 `last_error`,**保留库中旧数据不清空** |
| HTTP 404 | `status='invalid'`,此后不再扫描,admin 可删除该行 |
| 输入 bars < 120 | `status='insufficient'`,不写信号 |

## 调度与补算

**cron:`30 21 * * 1-5`,时区显式传 `UTC`**(`node-cron` 的 `{ timezone: 'UTC' }`,
不依赖容器 TZ)。

从实测的 `meta.currentTradingPeriod.regular.end` 反推:港股 `08:10 UTC` 收盘,
美股 `20:00 UTC`(EDT)/ `21:00 UTC`(EST)收盘。21:30 UTC 卡在两者之后,
**一个 cron 覆盖两个市场的当日收盘**,对应北京时间次日 05:30。

节假日不需要交易日历:当天 Yahoo 不返回新 bar,全量重算 upsert 后内容不变,空跑无害。

**启动补扫:不做缺口检测。** 判断「缺了哪几天」需要交易日历(港股与美股假期还不同),
复杂且易错。因为全量重算本就幂等,缺 1 天与缺 100 天走同一条代码路径,
**根本不需要知道缺了几天**:

```
服务启动 → 延迟 30s(不阻塞启动)
        → 读 site_settings['signals.last_scan_at']
        → 距上次扫描 < 6 小时?跳过 : scanAll()
```

6 小时闸门用于防止开发期反复重启导致反复扫描,复用现有 `site_settings` 表,
不引入新设施。

```ts
{
  symbol, name, market, closeRaw, currency,

}
```

## 权限与配置

- 看板与日志:与报告流同权限
- 「立即扫描」「改参数」「重新抽取标的」:**仅 admin**,复用 `/admin` 现有鉴权
- ATR 参数存 `site_settings`:`signals.atr_period`(默认 10)、
  `signals.atr_mult`(默认 3.0)。改完下次扫描全量重算,历史日志自动跟着变
- 新增可选环境变量 `SIGNALS=off` —— 整体关闭(不注册 cron、不启动补扫、
  路由返回 404),与现有 `TRACING=off` 的开关风格一致

## 已知取舍

- **看板数据是收盘口径,不是实时价。** 盘中打开看到的是上一个收盘状态,这是刻意的
  (见「非目标」)。界面上需明确标注数据截止的交易日。
- **周线用 ISO 周聚合**,与部分行情软件按「周一至周五自然周」的口径一致,
  但与个别按交易所日历定义周的软件可能有一根 bar 的差异。
- **复权口径与券商界面不同。** 信号用全复权序列算,与你在券商 App 里
  看未复权 K 线得到的 SuperTrend 会有差异,尤其是港股大额分红之后。这是刻意的 ——
  未复权序列算出的信号才是错的。
- **抽取是「宁缺毋滥」。** 只看标题,会漏掉正文表格里的 SQM / RIO / LIT 等一大批
  标的。这是明确选择:先保证自选股列表干净,召回率留给后续版本解决。
